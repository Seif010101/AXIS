# معمارية المنصة

المنصة دلوقتي **تطبيق واحد بـ Next.js 16** (TypeScript): الواجهة والـ API والسيرفر في نفس المشروع.
النظام القديم (Vue + FastAPI/Python + Supabase) اتشال بالكامل، ومحفوظ للرجوع إليه في الـ tag
`legacy-vue-fastapi` على GitHub.

## الصورة الكبيرة

```
المتصفح ──► Next.js (Hostinger, Node.js 22)
              ├── صفحات (React Server Components)        src/app/**/page.tsx
              ├── API المنصة                              src/app/api/v1/**
              ├── تسجيل الدخول (Better Auth)              src/app/api/auth/[...all]
              └── منطق السيرفر (أمان، صلاحيات، خدمات)     src/server/**
                        │
                        ▼
                  MySQL على Hostinger  (Drizzle ORM)
```

- **الاستضافة:** Hostinger، تطبيق Node.js مربوط بالـ repo `Seif010101/AXIS`، فرع `main`.
  أي push على `main` بيعمل build ونشر أوتوماتيك.
- **قاعدة البيانات:** MySQL على Hostinger. الجداول بتتعمل وتتحدّث أوتوماتيك لما السيرفر يقوم
  (مفيش حد محتاج يدخل phpMyAdmin).
- **تسجيل الدخول:** Better Auth: جلسات في الداتابيز، cookie محمية (httpOnly)، رمز Microsoft
  Authenticator إجباري للمالك والمدير والإداري، وإعادة إدخال الرمز قبل أي عملية خطيرة.

## إزاي التغيير بيوصل للموقع

1. تعديل على الكود → commit → push على `main`.
2. Hostinger بيلاحظ الـ push ويعمل: `npm install` ثم `npm run build` (دقيقتين تقريباً).
3. السيرفر الجديد يقوم → `instrumentation.ts` يطبّق أي migration جديد على الداتابيز.
4. `/api/health` يرجّع `{"status":"ok","database":"ok"}`.
